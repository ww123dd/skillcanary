# 知乎发布稿

标题

- 为什么给 AI 写的规则越来越多，AI 却越来越难用？
- 模型升级之后，你的规则是不是在拖后腿？

正文：

先说一个很多人没意识到的事实：**规则的核心问题不是写得对不对，是它有没有被加载。**

你写了一条规则，放在 skill 文件、prompt 或者 AGENTS.md 里。你以为它生效了。其实它经常没被读到——上下文太长被裁掉，任务不走那条分支，懒加载到需要的时候已经晚了。没被加载的规则，和没写过完全一样。

接下来的问题会一层层叠加：

规则越积越多，上下文越来越挤，注意力被稀释，规则之间开始互相打架。AI 不是越来越听话，是越来越难用。

然后是模型升级。你为弱模型写的那些"别这么干、必须那么干"，到了强模型身上反而成了枷锁。因为规则约束的是**过程**，模型越强，越容易被旧规则拖住。

最难的是：你根本不知道改动有没有落实。规则加载了吗，执行了吗，这次变好是真的还是碰巧？

很多人会说"那就让 AI 记住教训，下次别再犯"。但"记住"本身也要靠加载和注意力，它还是会漏。

所以我的结论是：这件事不该在规则上解决。**把每一次翻车变成一道必须通过的题。** AI 记不记得住不重要，它必须过了这道题才能合。

规则约束过程，机制约束结果。模型越强，过题应该越容易，而不是越被旧规则捆住。

我把这个思路做成了 SkillCanary：没有 case 或确定性目标，改动不许合；判分只认能从外部重新算出来的事实；隐藏测试、答案收起、污点扫描，抄答案式通过不算通过；Pass^k 看稳定性；判据漂了，旧结论作废。
