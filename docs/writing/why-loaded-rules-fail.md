# 为什么给 AI 写的规则越来越没用

先说一个很多人没意识到的事实：规则的核心问题不是写得对不对，而是**它有没有被加载**。

你写了一条规则，放在 skill 文件、prompt 或者 AGENTS.md 里。你默认它生效了。但它经常根本没进上下文：任务走了另一条分支，那条规则压根没被触发；上下文太长，它被裁掉了；或者等到懒加载把它读进来的时候，那一步已经做完了。

没被加载的规则，和没写过完全一样。你甚至不会发现，因为"没生效"和"本来就不需要它"看起来一模一样。

第二堵墙是堆积。

规则越多，上下文越挤。注意力被稀释之后，AI 不是越来越听话，而是越来越难用：旧规则和新规则开始互相打架，而没人敢删——因为没人能证明哪一条真的在起作用。于是规则只增不减。

第三堵墙是模型升级。

这一点最反直觉：你为弱模型写的那些"别这么干、必须那么干"，到了强模型身上反而成了束缚。当初那条规则是因为模型做不到才加的，现在模型做得到了，规则还在拦着它。

规则约束的是**过程**。所以模型越强，越容易被旧规则拖住。

第四堵墙是落实。

改了一堆东西之后，你其实不知道这次改动到底有没有落地：规则加载了吗，执行了吗，结果是真的变好了，还是刚好碰巧？

于是很多人会说："那就让 AI 记住教训，下次别再犯。" 但"记住"这件事本身也要靠加载和注意力——它还是会漏，只是你不知道它什么时候漏。

所以我的结论是：**这件事不该在规则上解决。**

正确的做法是把每一次翻车变成一道**必须通过的题**。AI 记不记得住不重要，因为它必须过了这道题才能合。规则约束过程，机制约束结果——模型越强，过题应该越容易，而不是越被旧规则捆住。

具体来说，每次改动只问三件事：

1. 这次改的是哪道题？如果答不上来，这就不是修复，只是一次编辑。
2. 改之前它是不是坏的？证据在哪？没有 baseline，你事后分不清"修好了"和"本来就没坏"。
3. 改之后，是同一道题、同一套判据重新跑出来的吗？别的题有没有被弄坏？

如果判据本身会漂（用例改了、环境变了、契约变了），那旧结论就得作废，否则你是在拿过期的事实给自己盖章。

我按这个思路做了 SkillCanary，它就是这个"必须通过的题"加上一台判分的机器。零依赖，两条命令就能看到它在问什么：

    git clone https://gitee.com/review-for-qing-lazy/skillcanary
    cd skillcanary && npm run demo:case

这个 demo 会跑三次：一次是没有证据的改动（失败），一次是有 case 和证据的改动（通过），第三次是把刚刚通过的那份改动只改短一个字段（又失败）。第三下是关键——它说明判据是活的，不是两个摆好的样本。
